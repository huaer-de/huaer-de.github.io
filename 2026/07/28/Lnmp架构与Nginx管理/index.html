一、Nginx 反向代理与负载均衡

（一）实验前梳理

1. 反向代理

  • 代理，相当于一个服务台，帮我们和后台联系交接。
  • 我们不知道后台到底是怎么服务的，具体步骤对客户端透明。
  • 反向代理是客户端的**”入口统一管家”**——客户端只访问 Nginx，由 Nginx 决定将请求转发给谁，并把结果返回给客户端。
  • 反向代理主要做五件事：负载均衡、隐藏真实服务器、转发请求、缓存加速、协议转换。
  • 需要定义一个后端服务器池，通过代理将请求转发给后端池，并传送客户端的真实 IP 给后端。

2. 负载均衡

  • 负载均衡概念之前已讲过。
  • 本节课新内容：
    • 权重：给性能好的服务器分配更多请求。
    • backup 备用服务器：所有主服务器都挂了，才启用 backup（通常是代理本身）。backup 不能用在 ip_hash 算法下。
    • IP Hash 会话保持：同一个客户端 IP 固定分配到同一台后端服务器，适用于购物车、登录状态等需要会话保持的场景。
    • CDN 场景下 IP Hash 失效：需要用 Cookie 代替 IP 做会话保持，即 Sticky Cookie 会话保持。编译好第三方 sticky 模块，给客户端下发名为 srv_id 的 Cookie 即可解决。

小知识：PowerShell vs CMD

  • CMD：古老 Windows 原生命令解释器，从 DOS 延续而来，不识别 Linux 原生命令（如 ls、grep）。
  • PowerShell：微软新一代现代化 Shell，专门替代 CMD，兼容更多写法，管理系统能力更强，更适合运维管理。
  • 浏览器访问域名，第一次返回 200，后面返回 304，看到了对应的 Cookie 且 Cookie 值没有变化。

HTTP 常见状态码速记：

  • 200：正常，拿到页面
  • 301：永久跳转
  • 304：文件没变，用本地缓存
  • 403：找到了但不给看（防盗链/权限）
  • 404：文件找不到
  • 502：代理连不上后端 Web
  • 规律：2xx 成功，3xx 重定向/缓存协商，4xx 客户端错误，5xx 服务端错误。

二、Nginx 安全控制

（一）含义

Nginx 安全控制的核心是保护服务器不被”挤爆”或”拖死”，有四个核心功能：

功能 指令 作用
并发连接数限制 limit_conn 限制单个 IP 同时能建立多少个连接，防止恶意占用资源
请求速率限制 limit_req 限制单位时间内请求数量，防止 CC 攻击或爬虫暴力刷接口
带宽限制 limit_rate 限制下载速度，防止单用户占满带宽
日志轮转 crontab 脚本 防止日志文件撑爆硬盘

三、Nginx 高级配置与管理

（一）理解

“安全控制”让产品能用，”高级配置与管理”偏向优化和运维便利性，让产品好用。主要学习五项功能：

功能 指令/工具 作用
自动索引 autoindex on; 浏览器访问目录直接列出文件，方便临时查看/下载
缓存配置 expires 30d; 设置静态资源缓存有效期，省带宽省 CPU
站点访问控制 deny/allow 配合 IP 或 IP 段限制特定路径访问，保护敏感目录
HTTPS 配置 SSL 证书 + 强制跳转 防窃听防篡改，登录/支付等敏感信息必须加密
日志可视化 GoAccess 工具 实时监控网站健康度，不用手动翻几十 GB 日志
