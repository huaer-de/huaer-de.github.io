一、Nginx反向代理与负载均衡​

（1）在实验开始前，我们先理清要做什么

1. 反向代理

代理，相当于一个服务台，它帮助我们进行交接，帮我们和后台联系。

但这也让我们不知道后台到底是怎么服务的。具体的步骤对我们来说，是透明的。反向代理是客户端的“入口统一管家”——客户端只访问 Nginx，由 Nginx 决定将请求转发给谁，并把结果返回给客户端。

反向代理主要做五件事：负载均衡、隐藏真实服务器、转发请求、缓存加速、协议转换。

我们需要定义一个后端的服务器池，通过代理，将请求转发给后端池，传送客户端的真实IP给后端。

2. 负载均衡

负载均衡的概念我们之前已经说过了。

这节课上，为了给性能好的服务器分配更多请求，我们给后端服务器加上了权重，如果所有主服务器都挂了，会启动backup备用服务器（通常是代理本身）。backup不能用在ip_hash算法下。

在需要会话保持的应用中（如用户购物车、登录状态不会丢），我们需要把同一个客户端IP固定分配到同一台后端服务器，这时候会用到IP Hash会话保持。

但CDN场景下IP Hash会失效，若想解决的问题，我们可以用Cookie代替IP做会话保持，我们需要用到Sticky Cookie 会话保持（CDN场景）。编译好第三方sticky模块，给客户端下发名为srv_id的Cookie就可以解决这个问题。

（2）具体实验

我们在server1上启动nginx服务，修改配置，修改server2对应的权重为2，在后面加上server4对应的备份界面。在这里，backup不参与正常流量分担。


（ps：这里server4对应的IP应该为192.168.63.130而不是131，我后面改了）

启动server2和server3的httpd服务，开始测试。然后关掉server2的httpd服务，只能访问到server3了。再关掉server3的httpd服务，发现访问到server4上了。

继续修改配置，在后端池里注释掉server4的备份界面，改为 server 127.0.0.1:8000 backup; ，将本机localhost的server提前，放在第一个server块，端口8000。测试时，访问到server1上了。

localhost如果不放第一个server块，Nginx会把负载均衡器自己当成默认主机，造成死循环，从而卡死访问不到正确界面。

下面我们操作IP Hash会话保持。在后端池开头加上 ip_hash ，注释掉backup相关内容，重启服务。发现在server3正常访问时，我们仍然只能访问到server2。

在CDN场景下，用Sticky Cookie进行会话保持时，我们先确认编译过sticky模块，然后重新修改配置。

注释掉ip_hash，加上 sticky name=srv_id expires=1h domain=.westos.org path=/; ，即给客户端下发名为srv_id的Cookie，Cookie 1小时后过期，Cookie的作用域名为所有westos.org的子域名，Cookie作用路径是全体。

在浏览器通过域名访问，在主机上进行域名解析。

这里我们可以了解一下PowerShell vs 命令提示符（CMD）的区别。简单来说，PowerShell更适合运维管理。CMD是古老 Windows 原生命令解释器，从 DOS 延续而来，不识别Linux 原生命令（ls、grep）；PowerShel是微软新一代现代化 Shell，专门用来替代 CMD，兼容更多写法，管理系统能力更强。

浏览器访问域名，第一次返回200，后面返回304，看到了对应的Cookie并且Cookie值没有变化。

状态码返回2xx代表成功，3xx为重定向/缓存协商（资源没有直接返回），4xx 为客户端错误（访问者/浏览器这边问题）。简单总结一下HTTP常见状态码。

状态码 含义
200 正常，拿到页面
301 永久跳转
304 文件没变，用本地缓存
403 找到了，但不给看（防盗链 / 权限）
404 文件根本找不到
502 代理连不上后端 web

二、Nginx安全控制​

（1）含义

Nginx安全控制的核心，是保护服务器不被“挤爆”或“拖死”。它有四个核心功能，分别为：

  • 并发连接数限制（limit_conn），限制单个IP同时能建立多少个连接，防止恶意占用资源，使服务器内存/CPU被耗尽；
  • 请求速率限制（limit_req），限制单位时间内的请求数量，防止CC攻击或爬虫暴力刷接口；
  • 带宽限制，限制下载速度，防止单用户占满带宽，如某个用户下载大文件（如10GB视频）把公司出口带宽占满；
  • 日志轮转（crontab脚本），防止日志文件撑爆硬盘。

（2）实验

为了限制并发连接数，我们在server块的外面，http里面加上 limit_conn_zone $binary_remote_addr zone=perip:10m; ，在内存开辟10MB空间记录每个IP的连接状态；以客户端IP为key。在download里通过 limit_conn perip 1 ，限制每个IP只能有1个并发连接。

我们在server4上，通过 ab -c 10 -n 10 http://192.168.63.131/download/vim.jpg 访问server1的图片，输出日志，看到大部分都被限制了（503 Service Unavailable）。

限制请求速率（限流），我们加上 limit_req_zone $binary_remote_addr zone=one:10m rate=1r/s; 和 limit_req zone=one burst=5 nodelay; ，每秒处理1个请求，允许5个请求排队，超出队列的直接拒绝。

正常情况下，访问10个请求，有 1r/s + burst(5) = 6 个成功，4个会503。

限制速率即带宽限制，在download添加 limit_rate 100k ，即单连接限速100KB/s，这样在单线程下，测速稳定在100KB/s左右，多线程下，每个100KB/s，总带宽约500KB/s。

因为有limit_conn，只用单个wget下载时，返回200，但ab(ApacheBench)测压时，只能返回一个200，其他超出限制了。

三、Nginx高级配置与管理

（1）理解

上面我们的“安全控制”功能，让产品能用，而“高级配置与管理”更偏向优化和运维便利性，让产品变得“好用”。我们要主要学习其中的五项功能：

  • 自动索引（autoindex on;）：方便临时查看/下载文件。开启后，用户直接浏览器访问这个目录就能看到所有文件名，不用一个个发链接。
  • 缓存配置（expires 30d;）：大幅提速。当下次再访问内容，会直接读本地，不经过服务器，省带宽、省CPU。
  • 站点访问控制（deny/allow）：保护敏感目录。使用deny和allow指令配合IP地址或IP段，限制对特定路径的访问。
  • HTTPS配置（ssl证书 + 强制跳转）：防窃听、防篡改。登录、支付等敏感信息必须加密传输，强制跳转保证用户永远走加密通道。
  • 日志可视化（go-access工具）：实时监控网站健康度。方便我们一眼发现问题，不用手动翻几十GB的日志文件。

（2）实验

实现Nginx自动索引，需要我们在专门的下载目录（如 location /download/ ）块里，开头加上 autoindex on ，开启服务。这样我们在浏览器访问文件夹时，如果没有index.html这类默认首页文件，不会直接返回403，而是自动生成页面，列出文件夹的所有文件，并提供下载链接。

不能在根目录 / 开启自动索引。否则用户能看我们整个网站文件结构，相当于把服务器所有文件都暴露了。

如果我们想添加缓存，可以在配置里加上含expires指令的 location ~ .*\.(gif|jpg|png)$ 模块。

expires 指令用于设置静态资源浏览器缓存有效期，自动添加Cache-Control与Expires响应头，可以在有效期内浏览器直接使用本地缓存，从而减少 Nginx 请求压力。

当我们再访问图片时，会有Expires行和Cache-Control（单位为秒）行，表示缓存信息。

白天有大量访问信息，日志不断写入access.log，占用大量硬盘。

我们可以编写shell脚本，实现 Nginx 访问日志轮转，将当前 access.log 按昨日日期重命名归档，发送 USR1 信号让 Nginx 新建空白日志文件。

再结合 crontab 定时任务，实现每日凌晨（零点）自动切割日志，避免日志文件持续增大占用磁盘。

在脚本中，mv access.log access_$(date +%F -d -1day).log 是把正在写入的访问日志重命名归档，%F = yyyy-MM-dd，-d -nday 是往前倒推n天。

USR1是Nginx的专用信号，若Nginx 发现原来的日志被改名，会自动新建一个全新空白 access.log。不会杀死Nginx。

下面我们部署GoAccess，以实现nginx日志可视化。GoAccess是一款开源、轻量的 Web 日志实时分析工具，专门用来解析 Nginx / Apache / Tomcat 的访问日志（access.log），可以快速统计网站访问数据，将Nginx 的访问日志生成可视化统计网页，并且不需要数据库。

为了与CentOS7兼容，我们安装1.8版本的goaccess（qwq，先跟着安了11和9，发现白安了）。进入软件目录，我们在检查有后ncurses-devel GeoIP-devel依赖库（终端面板支持、IP地理位置解析库）后，开始编译安装（make && make install），然后启动程序。

启动程序的命令还蛮长的，是 goaccess /usr/local/nginx/logs/access.log -o /usr/local/nginx/html/report.html --log-format=COMBINED --real-time-html & ，其中含义是先读取Nginx 访问日志 access.log，然后持续生成网页文件 report.html。--real-time-html 是实时刷新报表，新的访问记录会自动更新图表，末尾的 & 用来放到后台运行。

通过浏览器访问到日志内容。

看着内容虽然有点少，但配置应该没问题。多访问几次就好了……（应该）。

重新回到Nginx的配置文件，在里面添加监控模块(ngx_http_stub_status_module)，来查看 Nginx 当前运行连接、请求统计信息。

主机访问成功了。

继续修改配置，在本机server块内，location块外，加上 charset utf-8 ，可以解决中文乱码的问题。

一台Nginx服务器，只占用1个80端口，依靠访问的域名不同，区分打开不同网站，这就是域名虚拟主机。我们准备好网站目录与首页文件，写入首页内容web1。

在配置中，添加虚拟主机的配置，绑定好域名和对应的网站文件目录，重启服务。测试发现web1访问成功了。


下面进行http配置，即给网站www1.westos.org启用 https 访问（443 端口加密），让浏览器传输数据时，不再明文。

我们先通过系统自带 openssl 工具，在服务器 server1上，生成自签名SSL证书 cert.pem（同时包含公钥证书 + 私钥），然后修改nginx配置，添加HTTPS虚拟主机。

重载后，发现访问网站必须加上证书。

这里我们发现HTTPS加密网页端口是443（nginx），这是访问带SSL证书加密网站时用到的。
