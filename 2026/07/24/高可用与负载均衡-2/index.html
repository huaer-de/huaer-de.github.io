7.23 课程笔记：高可用与负载均衡-2

本次课继续讲解高可用与负载均衡，内容承接上一节，重点是 Pacemaker 集群管理、iSCSI 共享存储、Nginx 源码编译及七层负载均衡。

一、Pacemaker 集群管理与 Web 高可用

1. 知识点

（1）Pacemaker 是什么

  • Pacemaker 是 Linux 上的集群资源高可用管理软件。
  • 多台服务器组成集群，某台故障时，自动把服务、虚拟 IP 迁移到其他正常节点，保证业务不间断。
  • 常和Corosync配合使用，实现心跳通信。

（2）Pacemaker 与 LVS/Keepalived 的区别

维度 Pacemaker Keepalived
定位 通用集群资源管理器 LVS 高可用 + VRRP
管理对象 任意资源（VIP、服务、存储） 主要是 VIP + LVS 规则
复杂度 高，适合多资源编排 轻量，适合纯负载均衡场景
故障粒度 资源级（可单独迁移 VIP） 节点级（VRRP 倒换）

（3）高可用设计原则

  • 无状态服务最适合做高可用（Web 静态页、Nginx 反向代理）。
  • 有状态服务（如数据库）必须配合**共享存储（iSCSI）**才能做高可用。
  • 资源必须可监控（monitor operation），否则集群不知道它是否存活。
  • 生产环境必须开 STONITH，实验环境可关闭。

2. 上机实验

（1）初始化集群

  • 准备 server1 和 server4 两个节点，完成域名解析、免密登录、时间同步。
  • 安装集群套件和 Apache，防火墙放行集群及 HTTP 端口。

  • 启动 pcsd 管理服务，设置 hacluster 密码。
  • 在 server1 上进行节点认证，创建名为 myha 的集群，将所有节点启动集群并设置开机自启。
  • 用 crm_verify 验证配置，报错 config not valid。临时关闭 STONITH 机制跳过检验，使集群资源可以启动。

  • 创建浮动 VIP 资源 192.168.63.100，通过 pcs resource 查看启停状态。

（2）模拟故障测试

  • 通过 standby 模拟故障，将 server1 设为待机，VIP 自动漂移到 server4；恢复后 VIP 暂时不会自动回来。

  • 可强制切换资源：

（3）Web 资源与资源组

  • 删掉原有 VIP，重建新资源，并将 ClusterIP（VIP）与 WebSite（httpd）绑定到同一个资源组。
  • 遇到问题：ClusterIP 一直 stopped，启动失败，原因是未指定网卡，VIP 找不到匹配网卡。

二、iSCSI 共享存储搭建

1. 知识点

  • 现在需要引入共享存储，实现带外部存储的 MySQL 高可用集群，并整合进 HAProxy 负载均衡架构。
  • 名词解释：
    • target：iSCSI 服务端（提供磁盘）→ server2
    • initiator：iSCSI 客户端（取用磁盘）→ server1
    • IQN：iSCSI 设备唯一标识
    • LUN：服务端对外共享的磁盘单元

2. 实验

（1）服务端（server2）搭建 target

  • 为虚拟机新增一块硬盘 /dev/sdb。
  • 安装 targetcli（CentOS 7 上管理 iSCSI 服务端的命令行工具）。
  • 启动 target 服务，在交互界面创建后端存储（本地块设备 /dev/sdb 命名为 my_disk，交由 iSCSI 管理）。

避坑：targetcli 服务一开始搭建不好，后来发现是之前 target.service 配置文件写错，改回后正常。

（2）客户端挂载远程磁盘（server1、server4）

  • 两台客户端都安装 iSCSI 工具，编辑客户端的 IQN，使其与 server2 的 ACL 允许名称一致。
  • 扫描 Target，登录远程 iSCSI 磁盘。
  • 在 server1 上对磁盘分区，创建 XFS 文件系统。
  • 安装 MariaDB 数据库，将共享磁盘分区挂载到 MySQL 数据目录，实现数据库数据存放在网络共享存储上。

  • 当前资源组 dbgroup 包含三个资源：vip（虚拟 IP）→ iscsdb（Filesystem 共享存储挂载）→ mariadb（数据库），均正常运行在 server1 上。
  • 注意：server4 上没有登录 iSCSI，所以找不到 /dev/sdb1，集群资源无法漂移到 server4。
  • 解决方案：创建一个 iSCSI 客户端登录资源，放进资源组最前面，使资源启动顺序变为：
    iSCSI 登录资源 → vip → iscsdb(Filesystem) → mariadb
    这样集群切换时会先自动登录存储，再挂载磁盘。

三、Nginx 源码编译与负载均衡

1. 知识点

（1）为什么需要源码安装

  • 需要修改 Nginx 的部分功能，不能直接 yum 安装，必须用源码。
  • 大致流程：解压 → ./configure 勾选所需模块（如 SSL、状态模块，不需要的剔除）→ make 编译 → make install 安装到指定目录。

（2）平滑升级（Hot Upgrade）

  • Nginx 版本升级时网站不中断，用户无感知。
  • 升级时不关闭旧 Nginx，直接启动新版 Nginx 主进程；等所有老连接结束，旧 Nginx 退出，升级完成。

（3）关键配置参数

  • worker_processes：工作进程数，一般等于 CPU 核数。
  • worker_connections：单个 worker 能承载的连接数，受系统句柄限制。
  • user nginx nginx;：master 用 root 绑定端口，worker 降权运行，被攻击也无法提权到 root。
