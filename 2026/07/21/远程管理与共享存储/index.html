📅 早上：SSH、日志、定时任务 & 远程同步

这小节课的主题是：SSH 服务、NFS 远程文件同步、系统日志及定时任务的配置与应用

一、SSH 服务：安全的远程管理基石

（一）核心知识点

  1. SSH 服务与免密登录

    • SSH 是 Linux 系统最可靠的远程管理方式，通过非对称密钥实现加密通信。
    • 主要学习：systemd 管理方式（并行启动，比传统 init 快）、端口监听、ssh-copy-id 免密流程、安全配置加固。

  2. SSH 远程连接基础

    • 登录格式：ssh 用户名@IP 或者 ssh -l 用户名 IP
    • 不指定用户名？默认以当前身份登录远机～
    • 想直接用主机名连接？先配本地 /etc/hosts 解析，ping 一下通不通
    • 初次登录需要密码，是远端主机的账号密码哦
    • 结束啦？logout 或者 Ctrl+D 退出远程会话

  3. 重头戏：SSH 非对称密钥免密登录 ✨

  4. 多主机免密互联怎么搞？

    • 单台：客户端公钥推送到服务端，写入 authorized_keys 白名单
    • 多台：公钥可以累加！多客户端公钥都能加进去～

  5. SSH 免密登录要点

    • 密钥对默认存放：用户家目录下的 .ssh 隐藏目录
    • 单方向免密：客户端推送公钥到服务端即可
    • 多主机双向免密：共用一套密钥，同步 .ssh 目录到所有主机
    • 安全强化：可以改监听端口、禁用 root 登录、加用户黑白名单

（二）上机操作效果

1. SSH 单向免密登录

在 server1 上登录 server2 之前，先在 server2 上 ssh-keygen 生成密钥对：

  • /root/.ssh/id_rsa（私钥，藏好！）
  • /root/.ssh/id_rsa.pub（公钥，可以给出去）

交互的时候一路默认回车就好～

⚠️ 小插曲：首次 SSH 连接会缓存服务器公钥到 ~/.ssh/known_hosts。如果服务器 IP 变了（比如从 164 变成 174），再次连接会报错——因为缓存的公钥和实际不匹配啦！去文件里删掉旧条目就好～

二、系统日志管理

1. systemd-journald 日志持久化

默认 journald 日志在内存里，重启就没了 😭。持久化到 /var/log/journal 目录后，重启也能保留！

2. rsyslog 远程日志同步（日志集中收集）

  • 架构：server1 = 日志接收端，server2 = 日志发送端
  • 默认端口：514，支持 UDP/TCP

小知识点 🧀：

  • *.*：所有设施、所有级别日志
  • @IP = UDP 协议，@@IP = TCP 协议
  • 防火墙要放行 514/tcp、514/udp

😤 排错血泪史：客户端 nc 测试连不上服务端 514 端口，但 ping 正常……排查半天，发现是服务端防火墙 --reload 命令写错了根本没生效！（那错误很高级了）记住：改了防火墙规则一定要重启或 reload！

三、系统任务调度

1. 延时任务 at（一次性任务）

  • 依赖 atd 服务，服务没跑起来任务不生效！
  • 时间格式：now +10min、16:30、10:00 tomorrow

看到 You have mail in /var/spool/mail/root？说明输出发邮箱啦～
atrm 3 找不到任务？因为它是一次性的，执行完就消失了 OvO

😤 遇到的问题：

  • yum 源有问题导致 at 找不到 → 删损坏的 docker 仓库文件：rm -f /etc/yum.repos.d/docker.repo && yum clean all && yum makecache
  • 时间不同步 → timedatectl set-timezone Asia/Shanghai，然后 chronyc -a makestep，最后 date 验证 ✅

2. 周期任务 crontab（重复执行）

  • 基础语法：* * * * * 执行命令（分 时 日 月 周）
  • 0 和 7 都代表周日哦～

芝士点 🧀：

  • 黑白名单优先级：cron.allow > cron.deny
  • 系统级：/etc/crontab，用户级：/var/spool/cron/<用户名>

🤔 最小单位是分钟，怎么表示秒？用 sleep！其实这一分钟一直在运行的～

四、NFS 网络文件系统（网络共享目录）

  • 架构：server1 = 服务端（共享目录），server2 = 客户端（挂载使用）

核心参数：

  • ro：只读
  • rw：读写
  • no_root_squash：客户端 root 不压缩权限（保留 root 身份）
  • root_squash：默认，客户端 root 映射为匿名用户，权限受限

上机效果：

客户端创建挂载点 /mnt/nfs 后，写入 /etc/fstab（开机挂载），mount -a 生效～

😫 痛苦经历：df 命令卡死了！！！需要清理僵死的 NFS 挂载才能继续搞自动挂载……

芝士点 🧀：

  • NFS 支持通过 TCP/IP 网络共享资源
  • fstab vs autofs：fstab 开机永久挂载；autofs 按需挂载，闲置自动卸载，节省资源、避免网络断连后磁盘命令卡死！
  • autofs 的 /autofs 目录是内核自动管理的，不能手动 mkdir！
  • NFS 权限有三层：①服务端 /etc/exports 共享权限 → ②服务端本地目录 rwx 权限 → ③客户端挂载参数 ro/rw
  • 文件系统在服务端创建，客户端挂载就能用，网络通就行～

📅 下午：iSCSI 存储

五、iSCSI 存储

1. 是什么？

  • iSCSI = Internet Small Computer System Interface
  • 基于 TCP/IP 的块存储 SAN 协议，默认端口 3260
  • 作用：通过以太网把服务端磁盘裸设备共享给客户端，客户端识别成本地硬盘！

2. 角色分类：

  • 服务端：Target（提供磁盘块存储）
  • 客户端：Initiator（发起连接、使用远程裸盘）

3. 关键区别：iSCSI vs NFS 🔥

NFS iSCSI
提供的 文件系统 裸盘设备
文件系统在谁那创建 服务端 客户端
使用步骤 挂载直接用 分区→格式化→挂载
类型 NAS（文件级） SAN（块级）

NFS 挂载就能用，iSCSI 提供的是”裸盘”，要先分区格式化！iSCSI 属于 SAN 存储，文件系统在客户端创建，需要后端支持服务～

好啦，结束啦 ヽ(✿ﾟ▽ﾟ)ノ

下午小结：NFS 给你一个”共享文件夹”，拿来就用；iSCSI 给你一块”新硬盘”，自己分区格式化再挂载。都是网络存储，但层次完全不同～
