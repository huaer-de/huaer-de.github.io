早上：远程管理、日志与任务调度

这小节课的主题是：SSH 服务、远程文件同步、系统日志及定时任务的配置与应用。

一、SSH 服务：安全的远程管理基石

SSH (Secure Shell) 是管理 Linux 服务器最核心、最可靠的方式，通过非对称加密保证通信安全。

（一）核心知识点梳理

  1. 基础连接：

    • 登录格式：ssh 用户名@IP 或 ssh -l 用户名 IP。
    • 默认用户：不指定用户名，会以当前本地用户身份尝试登录。
    • 主机名连接：想直接用主机名（如 ssh server2），需先在本地 /etc/hosts 文件中做好解析。
    • 初次认证：首次连接需输入远端主机上对应用户的密码。
    • 退出会话：使用 logout 命令或按 Ctrl+D。

  2. 管理方式：

    • 学习重心是 systemd 的管理方式，其采用并行启动机制，与传统 init 不同，效率更高。
    • 服务管理命令：systemctl {start|stop|restart|status} sshd。

（二）上机操作与安全加固

  1. SSH 单向免密登录（密钥认证）
    原理：客户端生成一对密钥（公钥和私钥），将公钥上传到服务端的授权文件中。登录时，服务端用公钥加密挑战信息，只有持有对应私钥的客户端才能解密并正确回应。
    操作：

    # 在 server2 (服务端) 生成密钥对
ssh-keygen  # 一路回车，会在 /root/.ssh/ 下生成 id_rsa (私钥) 和 id_rsa.pub (公钥)
# 在 server1 (客户端) 将公钥上传至 server2
ssh-copy-id root@server2


    小插曲：known_hosts 文件会缓存首次连接的服务端公钥。若服务器 IP 变更（如从 164 变为 174），再次连接时会因公钥不匹配而报错，需在 known_hosts 文件中删除旧条目。

  2. 多主机双向免密互联
    场景：多台服务器之间需要频繁互传文件或执行命令。
    最佳实践：让它们共用一套密钥对。
    操作：

    • 在 server1 生成密钥对。
    • 将 server1 的 .ssh 目录完整同步到 server2。

      关键：多客户端的公钥可以累加写入服务端的 ~/.ssh/authorized_keys 白名单文件，实现“一对多”或“多对多”免密。

  3. SSH 安全加固（修改配置文件）
    编辑主配置文件 /etc/ssh/sshd_config，修改后需 systemctl restart sshd 生效。测试完务必改回，否则可能断连！

    # 修改默认端口，降低被自动扫描的风险
Port 2222
# 禁止 root 用户直接远程登录，提高安全性
PermitRootLogin no

    安全配置常用选项：

    • Port：监听端口号（默认 22）。
    • PermitRootLogin no：禁用 root 登录。
    • AllowUsers user1 user2：白名单，仅允许指定用户登录。
    • DenyUsers user3：黑名单，禁止指定用户登录。

二、远程文件传输：SCP 与 rsync

两者都依赖 SSH 协议，使用前必须确保 SSH 服务正常。

  1. SCP (Secure Copy)：全覆盖拷贝

    • 特性：支持双向、目录传输，是完整的拷贝。
    • 注意：普通用户创建的文件，用 scp 传输到远端后，默认会变成远端操作用户的文件。
    • 示例：scp server2:/mnt/paas ./ （双向免密后无需输密码）。

  2. rsync：灵活的增量同步利器

    • 核心优势：
      • 增量同步：仅传输有变动的部分，效率高。
      • 属性保留：-a 参数可同步文件权限、所有者等属性。
      • 灵活性：支持排除、删除等复杂同步规则。
    • 安装：源端和目标端都需安装 yum install -y rsync（若遇 yum 源问题，可清理旧缓存：yum clean all && yum makecache）。

三、系统任务调度

  1. 延时任务 at：一次性定时执行

    • 依赖：需 atd 服务保持运行。
    • 时间格式：灵活，如 now +10min, 16:30, 10:00 tomorrow。
    • 管理：atq 查看任务队列，atrm <任务号> 删除任务。
    • 排错经验：
      • at 命令找不到：检查 yum 源，安装 at 包。
      • 任务执行后查看邮箱 You have mail in /var/spool/mail/root，说明输出已邮寄。
      • 任务是一次性的，执行完会自动消失。
      • 执行时间不准：可能是时区/时间不同步。解决： 
        timedatectl set-timezone Asia/Shanghai
chronyc -a makestep
date  # 验证时间

  2. 周期任务 crontab：重复性定时执行

    • 语法：* * * * * 执行命令 (分 时 日 月 周)
    • 权限控制：黑白名单，cron.allow 优先级高于 cron.deny。
    • 任务存放：
      • 系统级：/etc/crontab
      • 用户级：/var/spool/cron/<用户名>
    • 技巧：crontab 最小粒度是分钟，实现秒级任务需结合 sleep 命令。例如，每30秒执行一次：* * * * * /path/to/script; sleep 30; /path/to/script。

四、系统日志管理：从本地到远程集中收集

  1. systemd-journald 日志持久化

    • 默认：日志存于内存 /run/log/journal，重启丢失。
    • 持久化：配置后存于磁盘 /var/log/journal，重启保留。

  2. rsyslog 远程日志集中收集

    • 架构：server1 (日志接收端)，server2 (日志发送端)。
    • 协议：默认端口 514，支持 UDP (@IP) 和 TCP (@@IP)。
    • 防火墙：服务端务必放行对应端口。
    • 排错经历：客户端 nc 测试连接不上服务端 514 端口，但 ping 正常。最终发现是服务端防火墙 firewall-cmd --reload 命令拼写错误，未生效。重启或重载防火墙后才能生效是铁律。

下午：网络共享存储：NFS 与 iSCSI

这小节主题是：NFS 文件共享与 iSCSI 块存储的应用与区别。

一、NFS 网络文件系统 (NAS 思想)

NFS 允许客户端通过 TCP/IP 网络挂载服务端共享的目录，像使用本地文件系统一样。

架构：server1 = NFS 服务端，server2 = NFS 客户端。

（一）核心参数与三层权限控制

  1. /etc/exports 核心参数：

    • ro / rw：只读/读写权限。
    • root_squash：默认，客户端 root 映射为匿名用户 (nfsnobody)，权限受限。
    • no_root_squash：不压缩客户端 root 权限，保留 root 身份，生产环境慎用。

  2. NFS 权限三层控制：

    • 第一层：服务端 /etc/exports 中的共享权限（ro/rw）。
    • 第二层：服务端本地目录的文件系统 rwx 权限。
    • 第三层：客户端挂载时的参数（ro/rw）。

（二）上机操作与排错

  1. 服务端配置：

    # server1: 安装、创建共享目录、配置导出、启动服务
yum install -y nfs-utils
mkdir /nfsshare
echo "/nfsshare *(rw,no_root_squash)" >> /etc/exports
systemctl start nfs-server && systemctl enable nfs-server
exportfs -r  # 重读配置文件，使改动生效

  2. 客户端挂载：

    # server2: 安装客户端工具、查看、手动挂载、开机挂载
yum install -y nfs-utils
showmount -e server1
mkdir /mnt/nfs
mount -t nfs server1:/nfsshare /mnt/nfs
# 写入 /etc/fstab 实现开机自动挂载


    /etc/fstab 示例：server1:/nfsshare /mnt/nfs nfs defaults 0 0

  3. autofs 自动挂载：按需挂载，防止卡死

    • 区别：
      • fstab：开机永久挂载，但若网络或 NFS 服务断连，可能导致 df 等磁盘命令卡死。
      • autofs：按需挂载，访问时自动挂载，闲置一段时间后自动卸载，节省资源，避免卡死。
    • 排错：df 命令卡死，往往是有僵死的 NFS 挂载。应使用 umount -l /挂载点 或 fuser -km /挂载点 来强制清理。
    • 注意：autofs 管理的挂载点根目录（如 /autofs）是由 automount 内核进程动态维护的，我们不能手动 mkdir 创建。
    • 原则：NFS 文件系统在服务端创建，客户端通过网络挂载即可直接使用。

二、iSCSI 存储：网络上的“本地磁盘”

iSCSI 是基于 TCP/IP 的 SAN (块存储) 协议，默认端口 3260。它通过网络共享的是裸设备，而非文件系统。

架构：

  • 服务端 (Target)：提供磁盘块设备。
  • 客户端 (Initiator)：发起连接，将远程磁盘识别为本地硬盘（如 /dev/sdb）。

（一）核心区别：iSCSI (SAN) vs NFS (NAS)

特性 NFS (文件共享) iSCSI (块存储)
提供层 文件系统 裸块设备
管理方 服务端管理文件系统 客户端管理文件系统
使用步骤 挂载后直接使用 连接 → 分区 → 格式化 → 挂载
类比 直接给你一个共享文件夹 给你一块全新硬盘，你自己分区

（二）上机操作与效果

  1. 服务端 (Target) 配置：

    # server1: 安装工具，进入 targetcli 交互环境
yum install -y targetcli
targetcli
# 在交互环境中，创建后端存储和共享
/>
/> cd /backstores/block
/> create disk01 /dev/sdb  # 将 /dev/sdb 设为共享的后端存储
/> cd /iscsi
/> create iqn.2026-07.com.test:server1  # 创建 target IQN
/> cd iqn.2026-07.com.test:server1/tpg1/luns
/> create /backstores/block/disk01
/> cd ../acls
/> create iqn.2026-07.com.test:client1 # 创建 ACL，允许此IQN的客户端连接

  2. 客户端 (Initiator) 配置：

    # server2: 安装工具，修改 initiatorname，发现并连接
yum install -y iscsi-initiator-utils
echo "InitiatorName=iqn.2026-07.com.test:client1" > /etc/iscsi/initiatorname.iscsi
systemctl restart iscsid
iscsiadm --mode discovery --type sendtargets --portal server1
iscsiadm --mode node --targetname iqn.2026-07.com.test:server1 --portal server1:3260 --login
lsblk  # 此时就能看到一块新磁盘，如 /dev/sdc


    后续步骤：对新磁盘 fdisk /dev/sdc 分区，mkfs.xfs /dev/sdc1 格式化，再 mount 挂载到某个目录即可像本地盘一样使用。
