2026.09.20

这次我们要学习的，是 Docker 网络，数据卷，安全相关的知识点。

那就开始吧。

一、 Docker 网络

（1）理解

Docker 容器默认有自己的网络命名空间，和宿主机是隔离的。如果想让外部访问我们的容器，就需要给容器加上端口映射。加上自定义网络后，容器就可以直接用名字通信了，这样，即使 IP 变了，也仍然可以访问到容器。

下面几个概念，我们得熟悉。

  • 原生网络（3个）：

    • bridge：默认模式，容器连到 docker0 网桥，分配 172.17.0.0/16 的 IP，外部不能直接访问，需要端口映射。

    • host：容器与宿主机共享网络栈，直接用宿主机 IP 和端口，但端口不能冲突。

    • none：容器只有 lo 回环，没有网卡，完全隔离。

  • 自定义网络（多个）：

    • 用 docker network create 创建的，默认驱动是 bridge。

    • 自带 DNS 解析，容器之间可以用容器名互相 ping。

    • 可以指定子网和网关。

  • 端口映射：

    • -p 宿主机端口:容器端口，通过 iptables DNAT 和 docker-proxy 实现。

  • container 模式：

    • --network container:容器名，新容器和已有容器共享网络栈，共用 IP 和端口。

二、 Docker 数据卷

（1）理解

之前提到过，容器默认的文件系统是只读的。我们的操作，是在最上面加一个可写层，在这个可写层运行的。但容器删除，可写层的数据也就没了。

于是，我们可以把重要的数据，从容器上用数据卷持久化到宿主机上。这样，也方便多容器共享数据。
Docker 有三种主要的挂载方式：

  • bind mount：直接挂载宿主机目录或文件到容器。路径自己指定，灵活，但依赖宿主机目录结构。

  • docker managed volume：由 Docker 自动管理卷，存放在 /var/lib/docker/volumes/ 下。路径不用自己管，移植性好，官方推荐。

  • tmpfs：挂载到内存，不持久化，容器停止就消失。

（2）实验

1. bind mount 挂载

在宿主机上，准备好挂载目录，把文件挂载上去。运行容器时，把宿主机 /tmp/data1 挂到容器 /data1，默认读写； /tmp/data2 的文件挂到 /data2上，默认只读。

[root@docker2 ~]# mkdir -p /tmp/data1 /tmp/data2
[root@docker2 ~]# echo "你好，这里是宿主机" > /tmp/data1/file1
[root@docker2 ~]# docker run -it --rm \
  -v /tmp/data1:/data1 \
  -v /tmp/data2:/data2:ro \
  busybox
/ # ls /data1
file1
/ # cat /data1/file1
你好，这里是宿主机
/ # touch /data1/file2
/ # ls /data1/
file1  file2
/ # touch /data2/file3
touch: /data2/file3: Read-only file system 
/ # exit
[root@docker2 ~]# ls /tmp/data1
cat /tmp/data1/file2
file1  file2

回到宿主机上，/data1/ 下的文件确实被改啦。

3. tmpfs 与跨容器共享卷

Tmpfs 用于临时加速，共享卷可以让多个容器协作。

① tmpfs 挂载

启动容器，挂载 tmpfs，写一些内容。再启动一个新容器，同样挂 tmpfs，内容没了。

[root@docker2 ~]# docker run -it --rm --mount type=tmpfs,dst=/data busybox
/ # echo "hello tmpfs" > /data/file1
/ # ls -l /data
total 4
-rw-r--r--    1 root     root            12 Sep 13 06:23 file1
/ # cat /data/file1
hello tmpfs
/ # exit
[root@docker2 ~]# docker run -it --rm --mount type=tmpfs,dst=/data busybox
/ # ls -l /data
total 0

② 跨容器共享卷

创建一个共享卷，写一点数据进去，在另一个容器上读取一下。

[root@docker2 ~]# docker run -it --rm -v shared_vol:/data busybox
/ # echo "data from A" > /data/a.txt
/ # exit
[root@docker2 ~]# docker run -it --rm -v shared_vol:/data busybox
/ # ls -l /data
total 4
-rw-r--r--    1 root     root            12 Sep 13 06:26 a.txt
/ # cat /data/a.txt
data from A
/ # exit

这次，内容还存在着，两个容器共享同一个卷。

4. 卷的只读挂载

创建卷并写一些数据，由于是只读挂载，只能读不能写。

[root@docker2 ~]# docker volume create ro_vol
docker run -it --rm -v ro_vol:/data busybox
ro_vol
/ # echo "read only test" > /data/file.txt
/ # exit
[root@docker2 ~]# docker run -it --rm -v ro_vol:/data:ro busybox
/ # cat /data/file.txt

三、 Docker 安全

（1）理解

容器默认对资源没有限制，一个容器可能吃光宿主机 CPU、内存、磁盘 IO，拖垮其他容器。

我们可以通过 cgroups 实现资源限制。Linux 内核的 cgroups（Control Groups）可以限制、记录、隔离进程组的资源使用。

（2）实验

下面的实验，仍然是在 docker2 进行的。

1. CPU 限制

① 绝对限制（20%）

启动容器，限制 CPU 在每个周期内最多用 20000 微秒，即 20%。

进入容器后，执行一个死循环消耗 CPU ，但实际 CPU 使用率会持续在 20% 左右。

[root@docker2 ~]# docker run -it --rm --cpu-period 100000 --cpu-quota 20000 --name cpu1 busybox

/ # dd if=/dev/zero of=/dev/null &

2. 内存限制

我们限制内存 200M，禁用 swap ，并给 /dev/shm 分配 300M 空间。

① 使用 150M 资源

[root@docker2 ~]# docker run -d --name mem1 \
  --memory 200M \
  --memory-swap 200M \

四、 lxcfs 视图隔离

（1）理解

容器默认会共享宿主机的 /proc 文件系统，在容器里执行 free -m，看到的实际上是宿主机的总内存，而不是容器的。这时候，有同学就开始不太理解了：明明限制了 200M，free 却显示 1.6G。

于是 lxcfs 的作用就显示出来啦。lxcfs 是一个用户态文件系统，它能把容器内文件替换成“按容器限制生成”的视图，让 free、top 看到的是容器实际可用的资源。

（2）实验

1. 安装 lxcfs

[root@docker2 ~]# yum install -y lxcfs
Docker CE Stable - x86_64                      2.9 kB/s | 2.0 kB     00:00
# ... ... ...()

Dependencies resolved.
Nothing to do.
Complete!
[root@docker2 ~]# systemctl enable --now lxcfs
Created symlink /etc/systemd/system/multi-user.target.wants/lxcfs.service → /usr/lib/systemd/system/lxcfs.service.
[root@docker2 ~]# ls /var/lib/lxcfs/proc/
cpuinfo  diskstats  loadavg  meminfo  slabinfo  stat  swaps  uptime

此时， lxcfs 的 proc 文件就生成了。我们挂载 lxcfs 文件查看效果。

2. 限制内存挂载文件

[root@docker2 ~]# docker run -it --rm -m 200m \
  -v /var/lib/lxcfs/proc/cpuinfo:/proc/cpuinfo:rw \
  -v /var/lib/lxcfs/proc/meminfo:/proc/meminfo:rw \
  -v /var/lib/lxcfs/proc/stat:/proc/stat:rw \
  -v /var/lib/lxcfs/proc/swaps:/proc/swaps:rw \
  -v /var/lib/lxcfs/proc/uptime:/proc/uptime:rw \
  busybox
/ #

参数中，-m 200m限制了 200M 的内存。我们把 lxcfs 提供的虚拟文件挂到容器内对应的 /proc 文件上，这样容器内读取 /proc/meminfo 时，看到的是 lxcfs 生成的“按 200M 限制”的视图。

五、 容器权限控制

（1）理解

默认容器内虽然是以超户 root 登录的，但权限仍然受到限制，比如不能改网卡、不能看磁盘。我们可以加上一些参数，打开容器权限。

  • --privileged：给容器几乎全部权限，近似宿主机 root，风险极高，慎用。

  • --cap-add：只添加指定的内核能力，按需授权，更安全。

这些参数的常见能力是：

  • NET_ADMIN：管理网络，如改网卡、加 IP。

  • SYS_ADMIN：系统管理，如挂载文件系统、fdisk。

  • SYS_MODULE：加载内核模块。

（2）实验

这个实验也比较短，主要是熟悉一下这两个参数的效果。我们通过加参数，不加参数，进入容器命令操作进行对比。

六、 Docker Swarm 集群部署

（1）理解

很多工具，最后都需要一个集群来分担流量，Docker 也类似。生产上我们会喜欢用 Kubernetes ，也就是传说中的 k8s ，它能管理的容器数量会更多。但我们先来了解一下 Docker Swarm 。

Swarm 是 Docker 引擎内置的集群管理工具，可以将多台 Docker 主机组成一个集群，统一调度容器。它适合小规模集群（十几台）的管理，上手比较容易。在这节实验里，我们先来了解下面的概念（但其实见得多一点，会发现看到名称，就能大概知道含义啦）。

  • Manager 节点：管理集群，下发指令，维护集群状态。官方推荐 3 个 Manager 做高可用，实验 1 个即可。

  • Worker 节点：只负责运行容器，不能下发管理指令。

  • Service：Swarm 中的服务，定义用哪个镜像、跑几个副本、映射什么端口。

  • 副本（replica）：一个 Service 可以跑多个容器实例，自动负载均衡。

  • ingress 网络：Swarm 自动创建的 overlay 网络，用于跨节点服务发现和负载均衡。

  • Token：Worker 加入集群的凭证，默认有效期约 24 小时，过期可以重新获取。
