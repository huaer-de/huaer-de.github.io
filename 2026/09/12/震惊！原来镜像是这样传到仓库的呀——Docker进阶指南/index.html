一、 镜像构建

（1）理解

Docker 镜像（Image）是静态的、只读的模板，用于存储和分发（就像.iso 文件）。由只读层（Read-Only Layers）堆叠而成。

镜像是由层组成的，每层代表一组添加、删除或修改文件的文件系统更改。

我们在镜像的基础上，启动它，让它开始运行，这就变成了容器。

Docker 容器是动态的、可写（临时）的，用于运行和操作（像正在运行的虚拟机，每个容器，都有自己的root用户权限、进程空间、用户空间和网络空间等）。

运行容器，会在镜像的最上面添加一个可写层（Writable Layer）。docker pull拉取镜像后，docker run就启动了容器。

下面的实验，我们从基础语法开始了解，熟悉后，构建一份 Nginx 镜像。

2. 使用 Dockerfile 构建

docker commit 虽然能工作，但无法审计、不可重复。我们更推荐 Dockerfile 构建的方式。

在 root 家目录下创建一个干净的构建目录，并编写 Dockerfile 。

[root@docker1 ~]# mkdir -p ~/docker-build && cd docker-build/
[root@docker1 docker-build]# vim Dockerfile
[root@docker1 docker-build]# cat DockerfilFROM  
busybox
ENV name world
ENTRYPOINT echo "hello, $name"令覆盖

这里的 Dockerfile 文件是老师的一个示例，相关的常用参数含义如下。

指令 说明
FROM 指定base镜像，如果本地不存在会从远程仓库下载。
COPY 、ADD 把文件从build context复制到镜像
src必须指定build context中的文件或目录
ENV 设置环境变量，变量可以被后续的指令使用
ENV HOSTNAME sevrer1.example.com
EXPOSE 如果容器中运行应用服务，可以把服务端口暴露出去：
EXPOSE 80
VOLUME 申明数据卷，通常指定的是应用的数据挂在点：
VOLUME [“/var/www/html”]
WORKDIR 为RUN、CMD、ENTRYPOINT、ADD和COPY指令设置镜像中的当前工作目录，如果目录不存在会自动创建。
RUN 在容器中运行命令并创建新的镜像层，常用于安装软件包
RUN yum install -y vim
CMD 与 ENTRYPOINT 这两个指令都是用于设置容器启动后执行的命令，但CMD会被docker run后面的命令行覆盖，而ENTRYPOINT不会被忽略，一定会被执行。
docker run后面的参数可以传递给ENTRYPOINT指令当作参数。
Dockerfile中只能指定一个ENTRYPOINT，如果指定了很多，只有最后一个有效。

二、镜像优化

（1）理解

最开始设计的版本，占用空间很大，我们可以通过下面的手段更新优化它。

选择最精简的基础镜像；少镜像的层数；清理镜像构建的中间产物；注意优化网络请求；尽量去用构建缓存；使用多阶段构建镜像。

FROM centos:7
COPY --from=build /usr/local/nginx /usr/local/nginx
EXPOSE 80

三、 公共仓库与私有仓库

（1）理解

下面，我们的进度来到了 Docker 仓库。本节内容，我们了解并区分一下 Docker Hub（公共仓库）和私有 Registry。

四、 加密并认证

（1）理解

刚刚创建的私有仓库，用docker2拉取镜像时完全没有加密，这是很危险的。

我们使用自签名证书，让 Registry 支持 HTTPS（端口 443），这就完成了加密。再创建用户密码文件，启用认证，我们就完成了用户认证。

这时候，不管从哪个设备访问 Registry ，就都需要用户密码啦。

（2）实验

五、 Harbor 企业级私有仓库

（1）理解

Docker容器应用的开发和运行离不开可靠的镜像管理，虽然Docker官方也提供了公共的镜像仓库，但是从安全和效率等方面考虑，部署我们私有环境内的Registry也是非常必要的。

Harbor 是由VMware公司开源的企业级的Docker Registry管理项目，它包括权限管理(RBAC)、LDAP、日志审核、管理界面、自我注册、镜像复制和中文支持等功能。

〇3 章外收尾

现在，我们仓库里library/nginx下，有5个版本啦。

不对不对，怎么一个签名都没有。

鲸鱼娘说，其实签名功能从一开始就没有被启用过。

在 Harbor 中，镜像签名（Image Signing）是通过 Notary 组件实现的，而我在部署 Harbor 时（./install.sh --with-trivy）没有启用 Notary 组件，推送镜像时（docker push reg.westos.org/library/nginx:v1）也没有开启 Docker 内容信任（DOCKER_CONTENT_TRUST=1）。

概念 作用 你的状态
加密 (TLS) 保证传输安全 ✅ 已启用（https://reg.westos.org）
认证 (Auth) 验证用户身份 ✅ 已启用（docker login 成功）
签名 (Notary) 验证镜像来源和完整性 ❌ 未启用（部署时未加 --with-notary，推送时未开 DCT）

Notary 对证书要求严格，配置不当会导致 Harbor 无法启动。我们在这里，就不签名了。

③ 配置默认仓库（docker2）
